Accessibility guidelines for labels and focus borders, primarily governed by Web Content Accessibility Guidelines (WCAG) 2.1 and 2.2, ensure that users navigating with keyboards or assistive technology can identify which element is active and understand its purpose. 
<empty-block/>
**Focus Border Guidelines (WCAG 2.4.7, 2.4.13)**
- **Visibility (Level A - 2.4.7):** A highly visible focus indicator (border or outline) must appear when an element receives keyboard focus.
- **Contrast (Level AA - 1.4.11):** The focus indicator must have a contrast ratio of at least **3:1** against the background.
- **Size (Level AAA - 2.4.13):** The indicator must be at least as large as a 2px thick perimeter around the component.
- **Non-Obscured (Level AA - 2.4.11):** The focused component must not be entirely hidden by other content.
- **No Removal:** Do not remove default browser focus outlines unless replacing them with a more visible alternative.
**Label Guidelines (WCAG 3.3.2)**
- **Programmatic Association:** Labels must be programmatically associated with their form fields using `<label for="ID">` or ARIA attributes (`aria-label`, `aria-labelledby`).
- **Positioning:** Labels should be placed consistently, typically above the form field or to the left, to ensure they are visible when the field is focused.
- **Persistence:** Labels must remain visible and not disappear when the user clicks into the field.
- **Instructional Text:** Provide clear, specific labels (e.g., "Full Name" rather than just "Name").
**Best Practices for Implementation**
- **Use Thick Outlines:** Use a thick (at least 2px) border or outline. Dashed lines may need to be 4px to meet area requirements.
- **Offset Indicator:** Use `outline-offset` in CSS to separate the focus border from the element, enhancing visibility.
- **Consistency:** Use a consistent focus style across the entire website.
- **Color Contrast:** Ensure the focus color contrasts with both the component and the background (e.g., a dark border on a light background, or vice versa).
- **Label Focus:** If the label itself is focusable, it must also have a clear, visible focus indicator.

# Power apps TabIndex accessibility warning in solution checker
“Tab index accessibility” warnings can come from a few places in Power Apps, and the fix depends on what you’re building:
- **Canvas app** (App checker)
- **Model-driven app** (Solution Checker)
- **PCF control** in a solution (Solution Checker)
Can you tell me which one you’re working with? In the meantime, here’s how to resolve it in each case.
---
## 1) Canvas App (Canvas Studio – *App checker* warning)
**Typical causes**
- Controls have **positive** `TabIndex` values (e.g., 1, 2, 3), which creates a brittle, non-standard tab order.
- Focusable controls that **shouldn’t** be in the tab order (icons, decorative images) have `TabIndex >= 0`.
- Important interactive controls are **excluded** (`TabIndex = -1`) unintentionally.
- Missing **AccessibleLabel** on interactive controls.
**Recommended pattern (WCAG-aligned)**
- Set **`TabIndex = 0`** for all controls that should be reachable by keyboard. Let the **natural layout** determine order.
- Set **`TabIndex = -1`** for **non-interactive/decorative** controls (icons used as images, shapes, separators).
- **Avoid positive** `TabIndex` values—these are discouraged and often trigger checkers.
- Provide **`AccessibleLabel`** on buttons, icons, images that convey meaning.
- Ensure focus **visible** state is sufficient (border/fill when focused if default isn’t obvious).
- Don’t hide focusable controls behind **Visible=false** toggles (bring them into the flow only when needed).
**Quick fix checklist**
- In the Tree view, select interactive controls → set `TabIndex` to **0**.
- Select decorative/disabled controls → set `TabIndex` to -**1**.
- For icons used as buttons:
	- `TabIndex = 0`
	- `AccessibleLabel = "Do <action>"`
	- Consider replacing with a **Button** (better default accessibility).
**How to verify**
- Run the app and tab through every screen using only the keyboard.
- Ensure focus moves **left-to-right, top-to-bottom** logically.
- Use the **App checker → Accessibility** and a screen reader (NVDA/JAWS/Narrator) to confirm labels are read correctly.
